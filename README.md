# Виртуализация терминала и интерактивный режим (Linux PTY)

Реализация небольшого PTY-обёртывателя на C. Она создаёт псевдотерминал, запускает дочернюю программу в отдельной сессии с управляющим терминалом и передаёт данные между терминалом пользователя и PTY.

## 1. Структура проекта

- `pty-run.c` - реализация PTY и двунаправленного relay-цикла.
- `Makefile` - сборка.

## 2. Требования

- Linux;
- компилятор C;
- заголовки libc для PTY;
- терминал, в котором `stdin` и `stdout` являются TTY.

## 3. Сборка

```sh
make
```

## 4. Запуск

Запустить локальную оболочку:

```sh
./pty-run /bin/sh
```

## 5. Что реализовано

1. **Создание PTY.** `openpty()` открывает master- и slave-концы псевдотерминала.
2. **Дочерняя сессия.** После `fork()` ребёнок закрывает master, вызывает `setsid()` и делает slave управляющим терминалом через `ioctl(slave_fd, TIOCSCTTY, 0)`.
3. **Перенаправление потоков.** `dup2()` направляет `stdin`, `stdout` и `stderr` на slave до `execvp()`.
4. **Raw-режим хоста.** Родитель сохраняет исходные настройки через `tcgetattr()`, создаёт raw-настройки `cfmakeraw()` и применяет их через `tcsetattr()`. Это отключает локальное эхо, каноническую буферизацию и часть обработки специальных символов на терминале хоста.
5. **Relay-цикл.** `poll()` отслеживает ввод с хоста и вывод из PTY. `write_all()` обрабатывает частичные записи и `EINTR`.
6. **Восстановление терминала.** Перед выходом родитель восстанавливает сохранённые атрибуты `tcsetattr()` и ожидает завершения дочернего процесса.

## 6. План проверки

Провека в обычном эмуляторе терминала:

1. `./pty-run /bin/sh` - ввод команд и вывод должны работать интерактивно.
2. `Tab` в позиции, где оболочка предлагает автодополнение.
3. `cat`, затем нажмите `Ctrl+D` для проверки EOF.
4. Выполнение длительной команды и нажматие `Ctrl+C`.

## 7. Управляющие байты и escape-последовательности

У терминального взаимодействия есть несколько разных уровней:

- **Управляющие символы ввода** - например, `Ctrl+C` соответствует байту `0x03`, `Ctrl+D` - `0x04`, `Esc` - `0x1b`. Их значение зависит от режима терминала и приложения.
- **Сигналы терминала.** В обычном режиме `ISIG` терминал может преобразовать `Ctrl+C` в `SIGINT` для foreground process group. В raw-режиме хоста `Ctrl+C` передаётся как байт. Если PTY slave настроен в обычном режиме, его line discipline может преобразовать полученный `0x03` в `SIGINT` для foreground-группы дочернего терминала.
- **Escape-последовательности** - последовательности, начинающиеся обычно с `ESC` (`0x1b`), например CSI `ESC [ ...`. Они используются для перемещения курсора, очистки экрана, изменения цветов и других команд терминального протокола. Приложения вроде `vim` и `htop` отправляют такие последовательности в stdout; эмулятор терминала хоста интерпретирует их.
- **Размер окна и терминальные возможности.** Полноэкранные приложения зависят также от корректного размера терминала (`TIOCSWINSZ` и `SIGWINCH`) и переменной `TERM`.

Escape-последовательности - это не то же самое, что `Ctrl+C`: первые обычно управляют отображением на стороне терминального эмулятора, а второй - специальный ввод, который может вызвать сигнал в зависимости от настройки line discipline.

## 8. Почему канонический режим хоста мешает интерактивным приложениям

В каноническом режиме (`ICANON`) драйвер терминала хоста собирает ввод построчно и обычно не передаёт его приложению до Enter. Поэтому приложение за PTY может не получить `Tab`, отдельные клавиши или последовательности клавиш вовремя. Локальное эхо (`ECHO`) также может отображать символы на хосте, а не позволять дочернему терминалу контролировать отображение. Это приводит к двойному эху, задержкам и поломке интерактивного редактирования.

В raw-режиме байты передаются практически без такой построчной обработки. PTY slave затем выполняет терминальную обработку для дочернего приложения. Это позволяет оболочке обрабатывать Tab, приложениям читать нажатия клавиш и использовать полноэкранный интерфейс.
